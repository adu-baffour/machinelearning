So, what exactly is machine learning?

Machine learning is a subfield of artificial intelligence.

It’s focused on building systems that learn patterns from data and make predictions — without being explicitly programmed.

Let’s break that down: The input is historical data — think of spreadsheets, sensor data, images, or text. The process is a learning algorithm — this could be linear regression, decision trees, or a neural network. And the output is a predictive model — a trained function that can make future predictions based on new input data.

Unlike traditional programming, where we write explicit rules, machine learning learns those rules from the data itself.

That’s what makes it so powerful for automation and pattern recognition.

Machine learning uses algorithms and models to make predictions and discover patterns in data.

A model is a mathematical function for describing the relationship between inputs and outputs and making predictions.

An algorithm is a procedure or set of decision rules used to carry out a machine learning task, such as making a prediction.

Machine learning combines tools and theory from computer science, artificial intelligence, statistics, and mathematics to make predictions and apply knowledge to new data.

What is an Algorithm?

\[\mathcal{A} : (\textit{data},\ \textit{hyperparameters}) \rightarrow f_{\theta^{*}}\]

  • 🗂️ Input: training data and hyperparameters
  • 🔧 Process: optimization rules
  • 🤖 Output: a trained model \(f_{\theta^{*}}\)
  • Ex: gradient descent trains regression models

Now, while the model is the function that makes predictions, the algorithm is what trains that model.

Think of it like this: the model is the structure, and the algorithm is the recipe for filling in that structure with the right values.

An algorithm takes: Input: training data and hyperparameters Processes: optimization steps, like gradient descent Output: a trained model with the best-fitting parameters

In math terms, we can write this as: A(data,hyperparameters)→fθ∗(, ) f^*_(data,hyperparameters)→fθ∗

For instance, SGDRegressor() in scikit-learn uses stochastic gradient descent to train a model. It updates the model’s weights gradually as it sees each data point. So again — the algorithm is the process, and the model is the result.

Model vs Algorithm

  • 🤖 Model: a mathematical function that makes predictions
  • ⚙️ Algorithm: a method that adjusts the model’s parameters using data
  • 📌 These terms are sometimes used interchangeably in casual conversation.

Let’s pause and clarify this distinction:

A model is the mathematical function that makes predictions. Once trained, it can be reused over and over to predict outcomes.

An algorithm is the method used to train the model. It iteratively adjusts the model’s parameters to reduce error.

This distinction is subtle but really important, especially when we start talking about training, optimization, and deployment.

Types of Machine Learning

  • Supervised — data has labels → Regression (predict a number) · Classification (predict a category)
  • Unsupervised — no labels, find structure → Clustering (group similar rows) · Dimension reduction (compress columns)
  • Reinforcement — learn from rewards

Let’s now take a step back and look at the big picture of machine learning types.

There are several learning paradigms, and choosing the right one depends on your task and the type of data you have.

First, we have Supervised Learning. This is when we train the model using labeled data — that is, we already know the correct answers. We use it for tasks like regression and classification.

Next is Unsupervised Learning, where we don’t have labeled outcomes. The model’s goal is to find patterns or structure — for example, clustering similar items together or reducing dimensionality.

Then there’s Reinforcement Learning, which is different — here, the model learns by interacting with an environment and receiving feedback in the form of rewards or penalties. This is used in areas like robotics or game-playing agents.

Later, we’ll also cover semi-supervised and self-supervised learning — two increasingly important techniques in modern ML.

The type of machine learning used depends on the machine learning task. Predicting the price of a rideshare trip based on distance and time is a supervised learning task, since the output feature (price) is known. Categorizing customers as “commuters”, “sports fans”, or “tourists” is unsupervised learning, since these categories are not an observed feature. Adjusting the price of a rideshare after a customer has declined is reinforcement learning. The prediction is updated based on the customer’s decision.

FOR NOTES: no labels: find structure

Let’s zoom in on supervised learning, which is the most common ML approach.

In supervised learning, we give the model a set of input features and the correct output — it learns the relationship between the two.

There are two major categories: Regression: This is when we predict numeric values. For example, predicting the price of a ride: $17.32. Classification: This is when we predict categories or labels. For example, classifying an animal as a cat or a dog.

A quick way to distinguish the two: If the output is a number, it’s regression. If the output is a label or class, it’s classification.

Now let’s look at reinforcement learning, which is different from the others.

In reinforcement learning, a model — called an agent — interacts with an environment, takes actions, and learns from rewards or penalties it receives.

Think of a self-driving car learning to stay in its lane. It receives positive feedback (rewards) when it does well — like staying centered. It receives negative feedback (penalties) when it makes mistakes — like crossing a lane.

Key components: The agent makes decisions The environment provides feedback The reward is the signal used to improve over time

This type of learning is often used in robotics, game AI, and recommendation systems.

Now we get into more nuanced learning strategies — starting with semi-supervised learning.

This approach uses a small amount of labeled data and a large amount of unlabeled data.

Why do this? Because labeling data can be expensive and time-consuming, but there’s usually lots of unlabeled data available.

Here’s an example: Suppose you have 100 ride records with labeled prices and 10,000 rides without prices. You train your model on the small labeled set, and then it begins to generalize by learning from the larger unlabeled set.

Semi-supervised learning is widely used in domains like medical imaging and natural language processing, where labeled data is rare but unlabeled data is abundant

Since labeling data is usually time-consuming and costly, you will often have plenty of unlabeled instances, and few labeled instances.

Some algorithms can deal with data that’s partially labeled.

Self-Supervised Learning

Next, we have self-supervised learning, which is one of the most exciting developments in modern machine learning.

In self-supervised learning, the model is trained without any human-labeled data — instead, it generates its own labels from the input data.

For example, in natural language processing: You take a sentence and mask a word: ‘The cab arrived at the ___.’ The model learns to predict the missing word — like ‘airport’ — using the surrounding context.

In computer vision, you might cut out part of an image and ask the model to predict what’s missing.

Self-supervised learning is behind the success of large language models like ChatGPT, BERT, and DALL·E.

It’s incredibly powerful because it lets us learn from vast amounts of raw data, without manual annotation.

Now let’s look at feature types, which are incredibly important in machine learning.

Features generally fall into two categories: Categorical Features: These are variables that represent categories or groups. They may be strings like ‘Regular’ or ‘New’, or numbers with no inherent order — like ZIP codes. Example: Yes/No values, Customer type

Numerical Features: These are measurable values where arithmetic operations make sense. Example: Age, income, transaction amount

One important note: just because a feature is stored as a number doesn’t mean it’s numerical in a mathematical sense. For example, ZIP codes are typically treated as categorical, because there’s no real arithmetic relationship between them. Knowing which features are which affects how we process and encode them.

Feature types Features in a dataset may be categorical or numerical. A categorical feature has non-numerical values, or numerical values without mathematical meaning. Ex: Yes/no, address, type of customer (regular, occasional, new). A numerical feature has numerical values with mathematical meaning. Ex: Amount spent on a transaction, square footage of a house. The actual values in a dataframe may not be enough to determine a feature’s type—context matters. Ex: Phone numbers are numerical, but mathematical operations on phone numbers have no meaning. Thus, phone numbers are categorical features.

Features in the rideshare dataframe can be classified as categorical or numerical. Categorical features have non-numerical values, such as cab type and destination. Numerical features have numerical values with meaning, such as distance, price, and surge multiplier. Time stamp is a numerical feature, since mathematical operations on time have meaning. Ex: 2018-12-01 is two days after 2018-11-29.

Classification models are supervised machine learning models that classify instances into a predicted level, or class, of a categorical output feature based on the input features.

Classification models may predict the class directly or the probability an instance belongs to a given class. In the probability case, predicted probabilities are compared against a threshold value to produce a class prediction.

In classification, input features may be categorical or numerical, but output features must be categorical.

FOR NOTES: Predict continuous numerical values Examples: Linear Regression, Regression Trees, k-NN regression Example use case: Predict the salary of an offer Output: real-valued number (e.g., $70,065)

Unsupervised Models – Clustering

  • Groups similar observations — no labels
  • Ex: K-Means, hierarchical clustering
  • Use: customer segmentation, behavior profiling
  • Output: cluster assignments (Cluster 1, Cluster 2)

What is clustering (Google Machine Learning Education, 2025)

Let’s revisit unsupervised models, starting with clustering.

Clustering algorithms group similar instances together, without any labels.

A popular method is K-Means Clustering: It assigns each instance to one of K groups based on feature similarity. Another is Hierarchical Clustering, which builds a tree-like structure of nested clusters.

Use cases include: Customer segmentation: e.g., grouping rideshare users into commuters, tourists, sports fans Behavior profiling: Identifying usage patterns or lifestyle segments

The output here is not a predicted value but a cluster label — like Group 1, Group 2, and so on.

FOR NOTES: Group similar observations together without labeled data Examples: K-Means clustering Example use cases: Customer segmentation and behavior profiling Output: Cluster assignments (e.g., Cluster 1, Cluster 2)

Unsupervised Models – Outlier Detection

  • Finds rare instances that break the pattern
  • Ex: DBSCAN
  • Use: fraud detection, error checking
  • No labels required — anomalies come from the data itself

Outlier Analysis in Data Mining (Scaler, 2023)

Another important type of unsupervised learning is outlier detection.

These models identify instances that are unusual or rare — meaning they don’t fit the general pattern of the data.

One useful algorithm here is DBSCAN, which can detect outliers as a byproduct of clustering.

Use cases include: Fraud detection: Spotting abnormal transactions Data cleaning: Identifying potential entry errors or system glitches

These models don’t require labeled data — they work by comparing each point’s behavior to others in the dataset. It’s a very practical technique, especially when working with real-world, noisy datasets.”

FOR NOTES: Identify rare or unusual instances that don’t fit the general pattern Example: Example use cases: Error checking No labels required — algorithm finds anomalies from data itself

Unsupervised Models – Dimension Reduction

  • Simplifies high-dimensional data, keeps the structure
  • Ex: PCA — combine distance & time into features capturing variance
  • Use: compression, noise reduction, 2D visualization

Dimension Reduction (Anna Schaar, 2023)

The third major category of unsupervised models we’ll look at is dimensionality reduction.

This technique is used to transform high-dimensional datasets into simple versions, while preserving as much useful information as possible.

The most common method is PCA — Principal Component Analysis.

PCA transforms the original features into a smaller number of new, uncorrelated variables called principal components.

Think of it like combining features that are strongly related into a single, more informative feature.

Example use cases include: Data compression: Reducing storage or transmission requirements Noise reduction: Removing irrelevant or redundant features Visualization: Reducing data to 2D or 3D so it can be plotted

Dimensionality reduction is often a crucial step before clustering or classification when your dataset has dozens or hundreds of features.

FOR NOTES: Simplify high-dimensional data while keeping important structure Example: Principal Component Analysis (PCA) Combine features (e.g., distance & time) into new features capturing variance Example use cases: Visualization (e.g., reduce to 2D for plotting)

Generalization: The Goal of Machine Learning

  • A model that memorizes its training data can score 100% on it and still be useless
  • What matters is performance on data it has not seen
  • That target is generalization
  • The test set estimates it: it simulates the future

FOR NOTES: A model that memorizes its training data can score 100% on it and still be useless. We do not care how well a model does on data it has seen. We care how well it does on data it hasn’t. That target — performance on unseen data — is called generalization. The test set exists to estimate it: it simulates the future.

What is Bias in ML?

  • Systematic error from overly strong assumptions
  • Persists no matter how much data you collect
  • High bias → too simple → underfits
  • Ex: predicting every ride’s price with one constant

Predicted vs. Actual (Monolith AI, 2023)

Let’s start with bias.

In machine learning, bias is not a social or ethical term — it refers to error caused by incorrect assumptions in the model.

More formally: The error for one instance is: ei=yi−y^ie_i = y_i - _iei=yi−y^i

The bias is the average error across all predictions: Bias=mean(ei) = (e_i)Bias=mean(ei)

A model with high bias is too simple to capture the true patterns in the data. It consistently underperforms — this is called underfitting. Example: using a constant value to predict ride prices would lead to large, systematic errors — regardless of the input.

A model without bias is unbiased — the mean difference between the predicted value and observed value is always 0.

Ex: Least squares regression is a regression model in which the weights are estimated such that the bias is guaranteed to be 0.

Bias may result from poor model fitting or violated model assumptions.

Underlying systematic errors in the data, such as underrepresenting a particular group or failing to measure an important feature, may also result in bias.

FOR NOTES: Bias is a systematic error from overly strong assumptions The part of the error that persists no matter how much data you collect High bias → model too simple → underfits. Example: predicting every ride’s price with a single constant.

What is Variance in ML?

  • How much predictions fluctuate across subsets of the same data
  • High variance → too complex → overfits
  • Right on one dataset, wrong on the next

Bias-variance decomposition for classification and regression losses (mlxtend)

Now let’s look at the other side of the coin: variance.

Variance refers to how much a model’s predictions fluctuate when trained on different datasets.

You might have a model that performs really well on the training data — but if it changes drastically with every new sample, it has high variance.

This is often a sign of overfitting — the model is memorizing the noise in the training set instead of learning general patterns.

So to recap: High bias = model is too simple → underfitting High variance = model is too complex → overfitting

Our goal is to strike a balance between these two.

Variance is the average squared difference between an observation and the mean.

Error variance is the variance of a model’s prediction errors.

Models with low bias and low error variance have predicted values that are consistently close to the observed values. A good model should have low bias and low error variance.

FOR NOTES: Variance measures how much predictions fluctuate across different subsets of the same dataset. High variance means model is too complex, thus, overfits training data Your model gets all answers right on one dataset but fails on new ones.

Bias-variance Trade-off

  • Simple models: high bias, low variance
  • Complex models: low bias, high variance
  • Goal: the sweet spot — best generalization

Bias–variance tradeoff (Wikipedia, 2025)

So how do bias and variance interact?

There’s a trade-off: Simple models tend to have high bias but low variance — they miss patterns but are stable Complex models have low bias but high variance — they capture detail but might not generalize

Your job as an ML practitioner is to find the sweet spot: A model that’s complex enough to capture key relationships But not so complex that it overreacts to noise

This is why we split data into training and test sets, and why we monitor model performance carefully during tuning.

Understanding this tradeoff helps you choose appropriate models, adjust their complexity, and improve generalization.

Archery target diagram: High bias: off-center grouping High variance: scattered shots Balanced: tight grouping near center

Prediction is like attempting to hit a bullseye on a target. A good model consistently (low error variance) hits the bullseye (low bias). A model with low bias and high error variance occasionally hits the bullseye but is less consistent. A model with high bias and low error variance consistently hits the same spot on the target, just not the center. The worst case scenario is a model with high bias and high error variance. Models with high bias and error variance are inaccurate and inconsistent.

FOR NOTES: High bias, Low variance Low bias, High variance Goal: Find the sweet spot where both are balanced for best generalization.

Machine Learning Workflow

  1. Frame — what is x? what is y? what is success?
  2. Get & split data — hold some data back
  3. Preprocess — clean, encode, scale
  4. Train — fit a model to training data
  5. Evaluate — metrics on held-out data
  6. Interpret & act — explain, decide, communicate

Here’s what a typical machine learning workflow looks like using scikit-learn.

Step by step: Load and split the data — using train_test_split() to create training and test sets Preprocess features — scale, encode, or impute values as needed Choose a model — such as LinearRegression or DecisionTreeClassifier Fit the model on the training data Evaluate on the test data — using accuracy, mean squared error, etc. Tune and deploy — improve performance, then move it into production if needed

This structure will be the foundation of everything we do in this course — we’ll refer back to this workflow again and again.

Input and output features are separated into two dataframes: X and y. Each estimator is loaded, or initialized, into the Python workspace. Any user-defined settings are specified during initialization. The .fit() method estimates model parameters, such as regression weights, or applies an algorithm to the input and output features. The .predict() method calculates predicted values for a set of inputs, either new values or the original inputs. The .score() method calculates a performance metric based on the type of machine learning task.
